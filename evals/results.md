# 实验结果

> **必读声明**
> 1. 这是**同一模型的自我评测**：A 组（通用提示）、B 组（本 skill 工作流）都由同一模型生成；样例、预埋问题、计分正则也由同一模型编写。**不是真实作者盲评**，没有人工母语审稿人参与。
> 2. 12 个样例是**自编中性段落**，**不是真实论文**，预埋问题偏典型，真实稿件更杂。
> 3. 计分正则是**代理指标**，且有部分是在看过 A 组输出后修正的（见“事后修正”），存在偏差。
> 4. v2 的改动有一部分由 v1 的实验发现触发，v2 在同一批样例上的重跑**不是独立证据**。
> 5. 本实验**不涉及也不证明任何“通过 AI 检测”的效果**。

## 1. 设置

- 样例：`evals/cases/01–12`（引言、理论框架、概念界定、翻译论证、引文、方法、DiD、OLS 结果、访谈编码、局限、引言、摘要），共 **85 个预埋问题**（冠词、时态、主谓一致、缺连接词、名词堆叠、“随着……发展”开头、冗余、含糊概括等）；每例带 `must_preserve` 清单、hedge 检查、flag_only 说明。
- A 组：提示词原样为 “Polish this academic paragraph.”，只输出润色文本（`runs/A/`）。
- B1 组：按 skill v1（`evals/skill_v1/SKILL.md`）流程：台账 → 三遍润色 → 保留审计（真实运行 `check_invariants.py`）→ 四部分输出（`runs/B1/`）。
- B2 组：按 v2 重做（`runs/B2/`）。**B2 不是从零重写**，而是在 B1 基础上应用 v2 触发的修正（见 §5），所以 B1→B2 的差异主要反映“已知缺陷被补上”。
- 计分：`python3 evals/score.py A B1 B2`，逐案结果见 `runs/score_all.json`。

### 事后修正（诚实披露）

看到 A 组输出后，我发现计分正则有 bug：部分用子串匹配造成假阴性（如 “family possess”“also point out”“and analyze”），个别 hedge 检查过严（“more like”“cautious”）。我修正了正则并重新生成案例、重新计分：A 的修复率由 97.6% 变为 100%，强度标记由 3 变 1；B1 的 12.7 项也由“未修”变为“已修”（B1 由 77/85 变 78/85）。**这次修正发生在看到 A 输出之后**，虽然是纠错、且对 A、B 一视同仁，但仍属事后调整。

## 3. 人工复核：新增论断 / 论证强度（逐段）

| 案例 | A 组 | B1/B2 |
|---|---|---|
| 01 | Many→**Numerous**（量词升级）；is helpful to→**promotes**（因果动词变强） | 无实质改动；开头“随着社会发展”被删，标“轻微”请作者确认 |
| 02 | very useful→**highly valuable**（评价略升，轻微） | 无 |
| 03 | **引语 "create" 被改成 "creation,"**（引语/术语被动） | 无 |
| 04 | always regarded→**often** regarded（作者的强断言被弱化）；hedge “to some extent” 的作用域从“意象与节奏”缩到仅“节奏” | 无；对论证跳跃提问 |
| 05 | 无 | 无 |
| 06 | 加 “rated on” 等，无实质 | 无 |
| 07 | 时态 increases→increased，无实质 | 无 |
| 08 | obvious→clear，无实质 | 无；对 “effect” 措辞提问 |
| 09 | 无 | 无 |

| 11 | 把“博物馆作用越来越重要”写成 **“Digital technology has transformed the role of museums”**（新增强因果论断） | 无；with the development→as … develops，标记并保持 |

汇总：A 有 **8 处实质性论断/指称改变**（01×2、04×2、10×1、11×1、12×2），另有 2 处轻微（02、10 的 can→could）和 1 处引语改动（03），其中 5 例（01、04、10、11、12）有实质改变，加上 03 的引语改动共涉及 12 例中的 **6 例**；B 的最终文本中**未发现**实质性论断改变（B1/B2 同）。这是我本人逐段人工判断，主观成分存在。

## 4. B 的真实弱点与失败（含 v1 缺陷）

1. **修复率低于 A**：B2 79/85 对 A 100%。未修的 6 项：
   - 1.3 “is helpful to”、2.6 “very useful”、9.7 “over-estimated”（连字符）、10.7 “between them”：**有意保留**（可接受变体或需要作者判断）；10.7 是提问而非忽略。
   - 12.3 “has increased”（报告结果的时态/语态）、12.4 “gradually becomes”：保守保留，属于判断题，正则把它们算作未修。
   - 8.1 “coefficient of” 在 B1 是**真实漏改**，B2 补上，但这条修改是看到结果后才加进 chinglish-patterns §L 的，所以 B2 的该项不是盲测。
   - “有意保留”是否应该算失败，取决于读者立场；我在此如实计为未修。
2. **v1 清单有缺陷**：
   - 案例 11 清单第 5 条的片段含省略号（`takes ... for example`），不能逐字查到。
   - 案例 06 把逗号拼接改为 “, and the mean age” 时新增的 `and` 没记入清单。
   - v1 的脚本对 three-fold→threefold 误报 “丢失 3”，B1 报告里**直接贴出 FAIL 而没有解释**。
3. **清单覆盖指标只是词集合级**，会高估；真实漏记可能不止我发现的。
4. **脚本不检查论断强度**：A 的 always→often（案例 04）脚本显示 PASS。强度审计依赖人工，且本实验中“人工”就是同一个模型。
5. **更啰嗦**：B 的输出多出清单、审计、提问三部分，阅读和核对成本更高；本实验没有测算耗时/Token。
6. **流畅度没有量化**：B 动得少（编辑比例约为 A 的 0.46 倍），保留了一些朴素表达；A 的文本在个别段落读起来更“顺”（如案例 01、11）。我没有设计流畅度评分，因此“B 是否更不自然”无法下结论。
7. **提问质量不能自证**：B 的作者提问是否有用，只能由真实作者判断。

## 5. 一轮修订（v1 → v2）及触发原因

| 改动 | 触发的发现 |
|---|---|
| `check_invariants.py` 忽略 `-fold` 复合词（threefold / three-fold） | 案例 02 误报 |
| SKILL.md：脚本 ERROR/WARN 必须逐条写处置，不得只贴 FAIL | 案例 02 报告 |
| SKILL.md / output-contract：清单片段必须逐字可查、不得用省略号；新增/删除连接词也要记；用 diff 对照做覆盖自查 | 案例 11 第 5 条；案例 06 漏记 `and` |
| SKILL.md：新增“该改 / 可保留 / 保留并提问”分界，明确非标准搭配（如 coefficient of）标准强度下不能留 | 案例 08 漏改（**测试触发，有“教考题”嫌疑**） |
| chinglish-patterns 新增 §L 统计报告搭配（41–45） | 同上 |

修订后（B2 对 B1）：清单片段不可查 1→0；脚本 ERROR 1→0（误报已除）；修复率 78→79；强度改变仍为 0；编辑比例持平。**这些改善大多是“把已知缺陷补掉”，不应解读为 skill 在新数据上变好。**

## 6. 结论（保守）

- 在这套自编样例上，通用提示几乎修完所有预埋语言问题，但同时有约一半案例出现论断/指称的改变，并改动了一处引语。
- skill 工作流在同样样例上做到了：保留项 0 丢失、论断 0 改变、改动可追溯，代价是修复率略低、输出更长、需要作者看清单。
- 这些结论受到自评、自编样例、代理指标和事后修正的限制。要验证真实价值，需要：真实作者的真实稿件、盲评（母语审稿人 + 作者本人对“有没有改变意思”的判断）、不同模型/不同提示的对照。
